## Tests made robust (no defect in the app)

| Test | Why it failed | Fix |
| --- | --- | --- |
| `TestATurnCarriesPicturesToASessionThatTakesThem` (agents/runtime) | The data race: the test swapped the agent's session while the runtime's exit watcher could read it. Nothing in the app swaps a session. | The swap waits until the runtime has recorded the session's end. |
| `TestConsumeCarriesOnAfterTheBusDroppedItAsSlow`, `TestConsumeSurvivesAPanickingHandler` (events) | Started the watcher in a goroutine and slept 100 ms; on a loaded machine the first events were published before it subscribed. | Uses `Watch`, which returns once its subscription is taken. |
| `TestTrackerWatchAndCoalescedEmission` (room) | Allowed at most four presence events for 51 changes; on a loaded machine publishing the 51 changes took six intervals. | The bound is one event per interval the publishing took. |
| `TestStopCancelsAPendingPermissionRequest` (agents/acp) | Hung for ten minutes once, under the race detector on a fully loaded machine: it waited for the agent's permission request without a limit and ignored the error of the turn it sent. Not reproduced in 200 runs (four at once, race detector on). | It fails within 30 s with what went wrong, and checks the turn was sent. |
| `TestADismissedFindingIsLeftOutOfTheCountsOfEveryLaterScan` (core, earlier today on Windows CI) | Read the scan history a moment before the finished scan was stored. | `scanOnce` waits until the scan is stored. |
| `flow.spec.ts` (e2e, Windows CI) | Compared the task page before and after a reload while its run was still finishing. | Waits for the run's own "completed". |

## Not changed (noted)

- **Evals report on a large history.** With 1500 tasks in its window the report takes about 0.8 s and is 1 MB: it reads each task's
  facts with a few queries (at most 2000 tasks, `DefaultMaxCohort`). It is one page with a loading state; batching those reads is
  worth doing if the page is opened often on a large workspace.
- **One empty folder per launch.** `proc.NoHooksDir` makes a fresh empty `drydock-no-hooks-*` folder in the temporary folder each
  time Drydock starts (a fixed name could be planted by another user) and never removes it. Windows' own clean-up of the temporary
  folder removes them; removing it when Drydock exits would be tidier.
- **Pages ask twice.** `needsyou.list` is asked twice when a page loads (the workspace's list and the open project's), and the
  Security scan page reads its history again once the projects are known. Each answers in well under a millisecond.

## Keeping it fixed

`ui/e2e/smoke.spec.ts` is part of the browser suite: every page must open with no uncaught error, no console error, no failed
request and no refused or failing call to the core, within 3 s for its heading and 1 s for each call (5 s for `github.projectRepos`, which starts git once a project and asks GitHub: 1.4 s for 60 projects on the Windows runner; 3 s for `connection.list`, which starts every agent CLI twice: up to 1.2 s on a loaded machine), without asking one method
more than six times; and moving around the sidebar must not grow the heap, the listeners or the DOM. It writes what each page cost
to `ui/test-results/smoke-report.json`. `internal/safe/nobarego_test.go` keeps every goroutine behind `safe.Go`.
