# UI audit, 2026-10-26

On the owner's words: "Do a full UI Audit, make sure the UI is in good shape, things are formatted nicely and designed well. Any
suggestions please send them over."

Scope: every route of the graphite UI (decisions P97, P98), 48 pages: the 44 fixed routes plus a task, its run, a chat and an agent's
own page, and the command menu. Method: the real app on the real core (`cmd/drydock-e2e`), seeded with one project, two agents, a
task waiting for approval, a second task in the backlog and a chat with one answer. A throw-away Playwright script (not committed)
took each page at 1440 x 900 in light (the first screen and up to three more scrolled down) and in dark, and at 1024 x 700 (171
screenshots); the first light screen of all 48 pages was read by eye, with 11 pages in dark and 3 at 1024 px. The causes were then found in the source and in a small Chromium measurement where the cause was
typographic. The density test of the last audit (`ui/e2e/density.spec.ts`) still holds its budget, so this audit looked for what
it cannot see: what looks wrong, reads wrong or is said twice.

Limits, said plainly: one populated project; the error states, a long list of tasks and the narrow window under 900 px were not
driven. Hover states that showed in a screenshot (the pointer was left over a row) were not counted. A finding is a defect when a
rule of the kit is broken (alignment, a target, a word the page uses for something else); everything else is a suggestion.

Severity: **High** = on most pages. **Medium** = on several pages or a whole surface. **Low** = one place.

## Suggestions (not changed)

Ordered by what a person would notice first. Each is small enough to do on its own.

### Layout and navigation

1. **Two items called Crew and two called Security in the sidebar** (the project's Crew under the project, the workspace's Crew and
   Security under Workspace; a project's Security is also a pill under its Overview). A person cannot tell from the sidebar which one
   they are on. Suggest "All crews" or "Crew (all projects)" for the workspace one, and "Security scan" for the workspace page (its
   title already says so).
2. **The sidebar stays 248 px wide at 1024 px.** On a list-and-detail page (Models, Agents, Integrations) the detail is left about
   390 px, and the task page loses its properties column. Suggest folding the sidebar to its rail under about 1200 px, the way the
   collapse button already does by hand.
3. **The page header is not one thing everywhere.** Most pages have an icon, a title, a subtitle and "Learn more"; GitHub has a
   breadcrumb ("Integrations / GitHub") and a "Guide" link; Models says "Guide" too; the project's Security page has no icon and is
   titled "Security scan" under a pill called "Security"; an agent's page has no header bar. Suggest one header with "Learn more"
   everywhere, and the same title as the pill.
4. **The details-panel toggle moves** between the top right corner (Crew, Agents) and the header row (Board, Overview). Suggest
   one place.

### Said twice

5. **Agents, Claude Code**: "Version not tested yet" (badge), "Untested" (list), and "Drydock has not tested version 2.1.310 yet"
   (notice), with **Test connection** both in the header and in the notice. Suggest the notice alone, with its one button.
6. **GitHub without gh**: the hero, the Access row ("Not installed") and a warning inside the connect form say it three times, and
   **Check again** is there twice. Suggest the hero alone, and the form's "Use the GitHub CLI sign-in" button turned off until gh is
   there.
7. **Task page**: the status is in the header pill, the Status property and the "Needs your decision" card (noted on 2026-10-19 and
   kept). An agent's page says "stopped" four times (hero chip, the Right now header, the activity block, presence).
8. **Room header**: "Project-wide discussion" under the title and again in "This is the start of the general channel".
9. **License** (a build without licensing): "Not configured in this build" in the subtitle, the notice's title, its first sentence and
   its last line say the same thing four times. Only a development build shows it, so it is low.

### Density and weight

10. **Routing**: every rule carries Edit, Disable and Delete (24 buttons on one screen). Suggest a "..." menu per rule or the actions
   on hover, the way the Integrations rows do it.
11. **An agent's page**: five actions stacked in the hero (Message, Edit, Inspect, Remove, All agents); Remove is a plain word. Suggest
    Message and Edit, the rest in a "..." menu, Remove in the danger colour and asking first.
12. **The activity block on an agent's page** is a filled accent card in light mode. Accent means "working" in graphite; a stopped
    agent's block in the accent colour reads as busy. Suggest the sidebar shade in both themes, the accent only while it works.
13. **The Scheduler strip on the board** is still one sentence of 100 characters with a chip in it ("up to 2 tasks in parallel; 0
    runs executing, 0 agent slots in use (peak 1)"). Suggest three small figures (Parallel 2 · Running 0 · Slots 0 of 2) and the
    link to Project settings.
14. **The run page's workflow graph at 70 %**: edge labels run under the nodes and are cut at the canvas's edge ("hen rejecte",
    "cha"). Suggest the labels on hover, or only for the edges of the selected node.
15. **Library cards**: the Details button sits at a different height in each card of a row (it moves when the chips wrap). Suggest
    a footer row pinned to the bottom of the card.
16. **Chat header** at 1440 px cuts three things at once (the title, the folder path, "runs in the project's ..."). Suggest the
    title alone in the bar, the folder and where it runs in the properties.

### Words

17. Integrations' subtitle "Connected once for the whole workspace · 0 on": suggest "0 connected".
18. Agent page: "$0.0002 spent in all 1 usage row": suggest "$0.0002 spent so far".
19. Inbox detail: "Reviewer: SHIP": suggest "Reviewer: approved". The task page still shows "Request kind: review".
20. Plan: the planner field's default is cut ("First agent with the pm or architect r..."): suggest "Automatic (pm or architect)".
21. The sidebar search box is cut ("Search or run a c..."): suggest "Search" with the Ctrl K chip.
22. Knowledge: the right-hand link of "Recently learned" is "memory" in lower case; the left one says "All requirements". Suggest
    "All memory".

### Small polish

23. Routing rules are code in JetBrains Mono with ligatures: `>=` draws as one glyph, `!=` as `≠`, `==` as one long bar. In an
    expression a person types, suggest `font-variant-ligatures: none` for code.
24. Table rows put text at the top and a button in the middle (Backups' Verify and Restore sit 6 px lower than the name).
25. Disabled primary buttons are a pale accent; in dark they read as a muddy grey-blue (New task, Create milestone). Suggest the
    outline style for a disabled primary, or keep it enabled and say what is missing on click.
26. The Inbox detail's "Open to review" is plain bold text that is a link; give it the link colour or the ghost button.
27. Security scan's folder field cuts both its placeholder and its hint at 1440 px ("C:\Users\you\Do..." and "a folder, not a
    pr..."). Suggest the hint under the field, or the placeholder alone.

## What works (keep)

The graphite tokens hold in both themes: no text was hard to read on the 11 dark pages read by eye (all 48 were captured), and the
contrast test checks every token pair. The density test still holds the type scale and the four weights the last audit set. The kanban card, the Inbox list and detail, the
Crew timeline, the Integrations list and detail and the run page's checkpoints are dense without being crowded. Empty states have
an icon, one line and the next step on almost every page. No page overflowed at 1024 px.
