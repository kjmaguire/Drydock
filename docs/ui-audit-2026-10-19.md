# UI audit, 2026-10-19

Scope: every route of the UI (41 pages: 38 fixed routes plus task detail, task run, an agent page and a room), at 1366x768 and 1024x700, light theme,
plus 8 pages in dark. Method: the real app on the real core (`cmd/drydock-e2e`) with one project, two agents and one task waiting for approval;
a throw-away Playwright script measured the live DOM (type sizes, gaps between neighbouring text, repeated text, long paragraphs, target sizes,
clipping) and took screenshots; a source scan of `ui/app` found the causes. The script is not committed. Nothing was fixed: this is the list.

Limits, said plainly: the screenshots show the first screen of each page (the page scrolls inside the shell), so the lower parts of long pages were
judged from the DOM metrics, not by eye. One populated project was used; empty, error and many-row states were not driven. The "too tight" metric only
sees text closer than 8 px to the next text, so it finds the worst cases, not every cramped layout. Nothing below is a defect in behaviour.

Severity: **High** = visible to every user or a rule of the whole UI is missing. **Medium** = visible on several screens. **Low** = polish.

## A. Layout and spacing

**A1 (High). There is no common page frame.** The left edge of the content is x=33 on project pages, 264 on pages with the workspace sidebar, 55 on Home's
Security scan, 251 on Project settings (a column about 820 px wide) and 319 on Settings and About. Widths are 1256, 1070, 820 and 960 for pages of the
same kind. Page titles carry an icon on about a dozen pages (Activity, Evals, Routing, GitHub, Plan, Security scan, Connections, Settings) and none on
Overview, Crew and Tasks. Only 5 screens render their own `<h1>`, but only 30 of the 127 screen files use `Page`/`PageHeader`, so the frame is by
convention, not by construction. The same Security panel is mounted at `/security` and `/security-scan` with different frames, so it looks like two
different pages.

**A2 (Medium). Text that touches text in a row.** Measured gaps: `WHEN` and `THEN` labels are 6.5 px from their code on every routing rule (8 of 8 rows);
the plan stepper's four steps are 7 px apart; `+1` and `-4` in the changed-files list are 6 px apart and the file list is 5 px from its status; on GitHub the
"License MIT" text is 6 px from "Docs"; on the task run page the workflow canvas touches the node inspector (1 px). Table cells themselves are padded
(none under 16 px), so the "tight columns" you see are inside rows made from `flex` and `grid` with `gap` of `4px`/`6px`, not in `<table>`s.

**A3 (Medium). Things overflow their card.** On the task page the `main` tag in the "Needs your decision" card runs about 20 px past the card edge, and the
branch name is clipped in two places (board card, side panel). Rooms clips its description at 1024 px.

**A4 (Medium). Columns of controls that do not line up.** On Connections the gateway rows right-align a checkbox with a label of changing length ("Let
cline use the gateway", "Let codex use the gateway"), so the checkboxes sit at x=1131, 1122, 1113 and 1118. The two-letter badges (`CL` for claude and
cline) are not unique. On Integrations the tile titles are vertically centred, so "Linear", "Notion", "Sentry" and "Aikido" start at y=330, 321, 330 and
339.

**A5 (Medium). Vertical rhythm.** In the left sidebar `Routing` and the `APP` group label have no gap. The Tasks board's Scheduler strip is one 140-character line of mixed text and a
button.

**A6 (Medium). Small targets.** 58 in total: 24 bare 15x15 checkboxes (Activity, Skills, Evals, Connections x6, GitHub, Security scan, Providers x3,
Backups, Data), 6 switches 30x18 on Project settings, filter chips 26 px high on Memory and 24 px on Chats, diff toggles 22 px on the task page, text
links 17-21 px high ("Manage crew", "All tasks", "cli.github.com", "Docs"). Settings has three 1x1 inputs (the theme radios); check that they are
reachable by keyboard.

## B. Type

**B1 (High). The type scale is not the type scale in use.** Tokens: 12, 13, 14, 16, 20, 24 px. Rendered: also 11.96, 12.88 (monospace), 19, 22, 28 and 30.
Page titles are 28 px/700 on 38 elements, a size no token has; 13 literal `fontSize` values (`12px`, `13.5px`, `19px`, `22px`, `24px`, `28px`, `30px`)
sit in the source. The same body text comes out as 13/400, 14/400 or 12/400 depending on the page.

**B2 (Medium). Eight weights.** 133 uses of 600, 84 of 500, then 650, 550, 700, 450 and 400. 450/550/650 cannot be told apart from their neighbours
with the variable font on a normal screen; they only add noise. Keep 400, 500, 600 and 700 (page title).

**B3 (Medium). Four monospace sizes** (11.96, 12, 12.88, 13 px) for paths, ids, JSON and code chips next to 13-14 px body text.

**B4 (Medium). Four levels of text before the content.** Routing is the typical case: title "Routing", subtitle "Model routing" (it says the title again),
a 7-line paragraph of 567 characters, then the section title "Routing rules" and its own help line. The same pattern is on Activity ("The event log" then "The
event log as the core persisted it ..."), Plan, Pulls, Security, Connections, Providers, Library and Evals. `introCss` exists 15 times in 15 files with 5
identical bodies, so the pattern is copied, not shared.

**B5 (Medium). Machine words in prose.** `WAITING_HUMAN` in a sentence ("A run is in progress (WAITING_HUMAN)"), `waiting_human` in the run header,
`room.presence_changed` as a type chip, `Request kind: review`. One state has three names: `stopped` (status bar), `Resting` (Overview card), `Paused
(stopped)` (side panel). Hedged plurals read as drafts: "task(s)", "run(s)", "slot(s)", "file(s) changed".

**B6 (Low). Title case is mixed**: "Evals report", "Settings and About", "Security scan", "Crew" and "Your crew", "Export and import", "Support bundle".

## C. Duplication

**C1 (High). The same fact is shown two or three times on one screen.**
- Overview: "nothing needs you" in the subtitle, in the "Needs you" section (a whole paragraph) and as "0 need you" in the Today tile; "0 merged today" in the
  subtitle and the Today tile and "Merged 0" in Insights; "2 agents" twice.
- Task page: the branch name three times (decision card, side panel, board card); status three times ("Awaiting your approval" pill, "WAITING_HUMAN" banner,
  "Needs your decision" card); Writer and Reviewer in the task panel and again in the right dock ("Team 2").
- Routing rule: priority as the `90` chip and again as "priority 90"; the action as a badge ("penalty: 0.5") and again as raw JSON next to it.
- Plan: "Goal" is the stepper step, the section title and the field label.
- Crew card: a presence dot, a status bar ("stopped"), and "No standing instructions." on every card.

**C2 (High). Repeated blocks per item.** Crew (847 words): each adapter repeats "Capabilities (absent means not verified)" x8, "structured output:" x8,
"model selection:" x8 and "Install guidance (Drydock never runs this for you):" x7. Integrations: "not connected" 9 times as a badge and again 4 times in
"Sync: not connected - Agents: not connected", "Tools for agents" 3 times. Activity: `task_4d3ed92374d7` 104 times and `run_71cde0aaa074` 50 times in a 125-row table.
These are reference tables printed as cards.

**C3 (Medium). Two URLs, one page.** `/mcp` renders exactly the same page as `/integrations` (311 words, identical headings); the navigation highlights
both. `/security` and `/security-scan` are the same panel in two shells (A1).

**C4 (Medium). Rule texts live on the screen.** The rules-licence help is in the Security page and the Security scan page; the gh install text is on GitHub in the alert and again inside it (the sentence "the GitHub CLI (gh) is not installed" is printed twice in one alert, once bold, once as a lower-case continuation); llama.cpp install is described twice on Providers ("Add a provider" and "Install llama.cpp" both x2).

**C5 (Medium). Source duplication behind the visual one.** `listCard` and `card` exist, but 85 files define their own card border, three files define the same
list-card body (`memory`, `requirements`, `task-list`), four screens define their own `detailsCss` (29 `<details>` in total), 92 hand-written
`gridTemplateColumns`, 16 `<table>`s that style themselves. Every one of these is a place where gaps (A2) and sizes (B1) can differ. The largest screen files are
`integrations-screen.tsx` (1014 lines), `local-models.tsx` (996), `skills-screen.tsx` (991), `scan-panel.tsx` (876), `agent-screen.tsx` (787).

## D. Too much, too little

**Too much** (ordered by words in the main area): Evals report 962 (a whole export printed under the tiles), GitHub 947, Activity 939, Project settings 910,
Crew 847, Security scan 629, Routing 503, Security 480, Settings 464, Providers 421. In these the first screen is prose. The 60 paragraphs over 200
characters are policy, mechanism or licence text, not instructions for the next click. Biggest: Routing 567, Settings (the variable list) 542, Budgets 462,
Connections 429, Library 418, Project settings 418, Evals 386.

**Too little** (where a person is left guessing):
- Activity: the Data column cuts the JSON at one line and no expand control was visible. Task cards cut the reviewer ("Worker One writes - Reviewer ...") and the branch.
- Overview "Passed first check n/a - no task checked in 7 days" and "Security -" tell what is missing but not what to do (run a scan, finish a task).
- Empty columns on the board say "Nothing here yet." without the next step; only "Up next" offers "Describe a task".
- The side dock (Terminal, Diff, Logs, Activity) is always at the bottom, also on pages where it has nothing to show (Home, Settings).

## E. What works (keep)

The dark theme looked right on the one dark page reviewed by eye (Security; the other 7 were captured, not inspected); the tiles and the kanban board have good rhythm; the main buttons are large enough;
no page overflows horizontally at 1024 px; the Appearance picker in Settings is a good example of "setting on the right, one line of explanation on the left".

## F. Proposal: a Guide, and a budget for the main UI

### The rule for the main UI

Every page keeps: the title (one size, one icon rule), **one** subtitle line (max 90 characters, never a restatement of the title), the controls, and the
data. Each section keeps at most one hint line (max 120 characters). Anything that explains *how it works*, *why it is built so*, *which licence*, *what
leaves the computer*, *how to install* or *what each value means* moves to the Guide, and the page gets a "Learn more" link to the exact topic. A paragraph
over 200 characters on a screen is a bug unless the test lists it as an exception.

### The Guide

- **Where**: a Guide entry (book icon) in the top bar next to Settings, `/guide` and `/guide/<topic>`, searchable through the existing "Search or ask anything"
  palette (index the topics there). Each page header gets an optional `guide="routing"` prop that renders "Learn more".
- **What it is**: Markdown topics in `ui/app/guide/*.md`, user language (not the developer docs in `docs/`), rendered with the existing hardened Markdown
  renderer, embedded in the exe so it works offline. A `<Term>` component gives a one-line tooltip for a glossary word and links to its topic.
- **Structure**:
  1. *Start here*: what Drydock is, the loop (task, worker, reviewer, approval, merge), the Overview in 60 seconds.
  2. *Concepts*: crew and roles, tasks and evidence, rooms, workflows and checkpoints, approvals ("Needs you"), delivery modes (local, pull request), budgets.
  3. *How to*: connect an agent CLI, sign in to GitHub with `gh`, connect a service or MCP server, scan a repository (and where to get rules), add a model
     provider or a local model, back up and restore, export a support bundle.
  4. *Reference*: the status words (one glossary: stopped = Resting = ... decided once), routing rule language (`WHEN` fields and `THEN` actions), event types
     (Activity), the variables agents inherit, adapter capabilities table, keyboard map, licences of rule sets and tools.
  5. *Safety and privacy*: what stays on the computer, what leaves (osv.dev package names, model calls), how secrets are stored, why text from outside is
     shown inert.
  6. *Troubleshooting*: `gh` missing, CLI not found, port or sandbox problems, "no CI reported".

### Fixes that are not about the Guide

1. One `Page` frame for all 41 routes (three width presets: reading 820, standard 1256, wide), one title style and one icon rule; mount Security once.
2. Type: add `--text-title: 28px` (or move titles to `--text-2xl`), delete the 13 literals, keep four weights, one mono size.
3. Row spacing: a shared `Field`/`Row` with a minimum 12 px between label and value and a `Meta` strip with `gap: var(--space-3)`; replace the 92 hand-written grids by the shared list/table kit.
4. Remove duplicates: C1 and C2 item by item (show a fact once, in the place that acts on it); `/mcp` redirects to `/integrations`; one word per state.
5. Targets: wrap the 15x15 checkboxes and 18 px switches in a 28 px hit area; links in toolbars get the ghost-button padding.
6. Text diet: the 60 long paragraphs, the Crew capability block (collapse per adapter or move to the Guide's capability table), Activity Data row opens a detail.

### Keeping it fixed

Turn the audit script into a permanent Playwright test (`ui/e2e/density.spec.ts`) with budgets: no paragraph over 200 characters outside an
exceptions list, every `h1` followed by at most one subtitle line, sizes limited to the token set, no text neighbour closer than 8 px, no target under
24 px, no horizontal overflow at 1024 px, no text repeated more than twice on a page outside tables. Add a unit test that every `guide=` prop resolves to
a topic and every topic is reachable from the search.

### Suggested order

1. Frame, tokens and weights (A1, B1-B3): one PR, mostly mechanical, biggest visible gain.
2. Guide shell, glossary and the first four topics (Routing, Security, GitHub, Settings), with the paragraphs removed from those screens in the same PR.
3. Remaining topics screen by screen; duplicates (C1-C3) as each screen is touched.
4. Spacing and targets (A2-A6), then the density test turned on with the exceptions list shrinking to empty.
